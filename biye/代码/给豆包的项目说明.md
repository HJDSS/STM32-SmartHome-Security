# 智能家居与安防项目：键盘连续输入与联网交互专项说明（给豆包）

> 目标：围绕 **矩阵键盘输入连续性、响应时延、误触发、ESP 联网时输入卡顿** 进行可执行测试与可落地优化。

---

## 1）可直接执行的实机压测用例

### 1.1 测试前准备（统一）

- 固件版本：记录 `build time / commit id`。
- 硬件连接：
  - 4x4 矩阵键盘、OLED、蜂鸣器、门锁继电器、PIR、MQ2、ESP8266。
- 供电：稳定 5V/3.3V，记录电源型号。
- 串口日志：建议开启 USART1 调试输出（如已支持）。
- 环境记录：温湿度、是否有电磁干扰源（风扇/继电器/电机）。

### 1.2 用例 A：快速连续 6 位密码输入

**目的**：验证连续输入不丢键、不“输入两位后卡死”。

**步骤**：
1. 进入密码主页（`Input Password` 显示）。
2. 连续输入 `1 2 3 4 5 6`，间隔分别测试：
   - 120ms/键（正常）
   - 80ms/键（较快）
   - 50ms/键（极限）
3. 每组执行 30 次。
4. 每次输入后按 `#` 触发校验（或按项目现有确认键流程）。

**判定标准（Pass）**：
- `PressNum` 能稳定增长至 6。
- OLED 星号回显数量与按键数一致。
- 无“按键无反应 > 300ms”现象。
- 30 次中 0 次丢键、0 次误键。

**异常记录项**：
- 时间戳、测试组别（120/80/50ms）。
- 实际按键序列 vs 系统识别序列。
- 卡顿时长（ms）、是否伴随蜂鸣异常。
- 当次 `security_alarm/mq2_emergency_alarm/ui_busy` 状态。

---

### 1.3 用例 B：输入中穿插报警状态切换

**目的**：验证按键交互优先级，确认报警逻辑不抢占输入。

**步骤**：
1. 开始输入密码 `1 2 3`。
2. 在输入第 3 位后触发 PIR（模拟入侵）或 MQ2 超阈值。
3. 继续输入 `4 5 6` 并确认。
4. 分别测试：
   - 仅 PIR 报警
   - 仅 MQ2 报警
   - PIR + MQ2 同时触发
5. 每种场景执行 20 次。

**判定标准（Pass）**：
- 报警触发后，后续 3 位仍可正常录入。
- 输入流程不被中断（不回首页、不清空输入）。
- 报警提示与蜂鸣行为符合设计，但不吞键。

**异常记录项**：
- 报警触发时刻与当前 `PressNum`。
- 是否出现输入被重置（`PressNum` 回 0）。
- 报警期间单键响应时延（建议人工录像帧统计）。

---

### 1.4 用例 C：ESP 联网收发压力下的人机交互

**目的**：验证 ESP 活跃收发时，本地键盘仍流畅。

**步骤**：
1. 使 ESP 保持在线（OneNET/AT 心跳进行中）。
2. 云端每 200~500ms 下发轻量命令（如状态查询/LED 控制）。
3. 本地连续执行：
   - 6 位密码输入 + 确认
   - `*` 取消
   - `D/#` 管理流程入口尝试
4. 持续 10 分钟。

**判定标准（Pass）**：
- 本地按键平均响应 < 120ms，P95 < 200ms。
- 无“输入两位后冻结”的长停顿。
- ESP 收发不中断或可自动恢复。

**异常记录项**：
- 卡顿发生时是否在 `UART2_Send_AT_Command` 或 `InitFsm` 阶段。
- 当时 `tls_inited`、`wifi_idle_ready_tick`、`ui_busy`。
- 串口缓冲是否溢出（`CLR_Buf/CLR_Buf2` 触发次数）。

## 2）4x4 键盘扫描状态机优化（可替换代码 + 集成步骤）

> 目标：解决“快速换键无响应/输入中断”，并强化“键盘交互优先”。

### 2.1 关键思路

1. **状态机修正**：`WAIT_REL` 状态下允许“键值切换直接接管”，不强制先稳定全松手。
2. **键盘优先**：当用户处于输入交互态（`PressNum/ReInputEn/ReInputReady/RegFingerprint`）时，暂停 ESP 轮询动作。
3. **统一 ui_busy 判定**：避免同一循环内多处重复且不一致判断。

### 2.2 可替换代码（`Driver/key4_4.c` 中 `Key_Scan`）

> 用下面函数整体替换现有 `Key_Scan()`。

```c
int Key_Scan(void)
{
    int raw;
    u32 now;
    int ret = -1;

    s_key_scan_count++;
    g_key_exti_pending = 0u;
    raw = key_scan_physical_once();
    now = key_monotonic_ms();
    key_stable_update(raw);

    switch(s_keysm)
    {
    case KEYSM_IDLE:
        if(s_stable != -1)
        {
            s_active_key = s_stable;
            s_press_t0 = now;
            key_emit_event(KEY_EVENT_CLICK, s_active_key);
            ret = s_active_key;
            s_keysm = KEYSM_WAIT_REL;
        }
        break;

    case KEYSM_WAIT_REL:
        if(s_stable == -1)
        {
            s_keysm = KEYSM_IDLE;
        }
        else if(s_stable != s_active_key)
        {
            /* 快速换键：直接接受新键，避免“前两位后卡住” */
            s_active_key = s_stable;
            s_press_t0 = now;
            key_emit_event(KEY_EVENT_CLICK, s_active_key);
            ret = s_active_key;
            s_keysm = KEYSM_WAIT_REL;
        }
        break;

    default:
        s_keysm = KEYSM_IDLE;
        break;
    }

    return ret;
}
```

> 说明：原 `KEYSM_PRESSED` 分支在当前项目策略下可简化不使用；若后续恢复长按语义，再单独恢复。

### 2.3 可替换代码（`User/main.c`：键盘优先外设调度）

> 在 `DEBUG_PASSWORD_ONLY` 主循环中，采用如下模式（核心片段）：

```c
u8 ui_busy_loop = 0u;
if((PressNum != 0) || (ReInputEn != 0) || (ReInputReady != 0) || (RegFingerprint != 0))
    ui_busy_loop = 1u;
#if !DEBUG_KEYBOARD_ONLY
if(g_debug_feature_panel) ui_busy_loop = 1u;
#endif

/* 键盘始终优先 */
BareMode_ScanAndDispatchKey();

#if EN_ESP8266_ONENET
if(!ui_busy_loop)
{
    if(!tls_inited)
        ESP8266_OneNET_InitFsm_Poll();

    UART_Remote_Ctrl();
    Security_Check_Serial_Command();

    /* 空闲窗口达到后才做联网/心跳 */
    if(wifi_idle_ready_tick < 100u) wifi_idle_ready_tick++;
    // ... OneNET_Parse_Cmd / 心跳 ...
}
else
{
    /* 交互中冻结联网动作 */
    wifi_idle_ready_tick = 0u;
}
#endif
```

### 2.4 集成步骤

1. 替换 `key4_4.c` 中 `Key_Scan()`（整函数替换）。
2. 在 `main.c` 的密码调试主循环中应用统一 `ui_busy_loop` 判定。
3. 保证 ESP 相关调用全部包裹在 `if(!ui_busy_loop)` 分支内。
4. 编译后执行本说明第 1 节压测用例 A/B/C。

## 3）密码输入防误触/防抖与边界场景实现

### 3.1 目标与策略

- **防抖**：保持现有三次多数表决 + 稳态队列。
- **防误触**：
  - 输入期间仅接受 `0-9/*/#/A-D` 合法键。
  - 重复同键长按不重复累计位数（可选）。
- **边界处理**：
  1. 输入中途取消（`*`）
  2. 长按按键
  3. 断电中途输入

### 3.2 代码实现（建议增量）

#### A) 输入超时自动清空（防半输入长期悬挂）

在 `main.c` 增加：

```c
static u32 g_pwd_input_last_ms = 0;
#ifndef PWD_INPUT_TIMEOUT_MS
#define PWD_INPUT_TIMEOUT_MS  10000u
#endif
```

在每次录入数字成功后更新：

```c
g_pwd_input_last_ms = Bare_GetTickMs();
```

在主循环周期检查：

```c
if((PressNum > 0) && ((u32)(Bare_GetTickMs() - g_pwd_input_last_ms) > PWD_INPUT_TIMEOUT_MS))
{
    DataInit();
    OLED_ShowString(0,16,"Input Timeout   ",16);
    OLED_ShowString(0,32,"Input Password  ",16);
    OLED_ShowString(0,48,"               ",16);
}
```

#### B) 长按不重复计数（防误触）

在 `KeyPress()` 数字分支前加“重复键保护”（可选）：

```c
static int s_last_digit_key = -1;
static u8 s_last_digit_hold = 0;

if(keycode >= 0 && keycode <= 9)
{
    if((int)keycode == s_last_digit_key && s_last_digit_hold)
    {
        return; // 抑制长按重复
    }
    s_last_digit_key = (int)keycode;
    s_last_digit_hold = 1;
}
else
{
    s_last_digit_key = -1;
    s_last_digit_hold = 0;
}
```

> 注：更精确做法是结合 `Key_GetLastEvent()` 的 `CLICK/LONG_PRESS` 区分，仅对 CLICK 累计。

#### C) 输入中途取消（已有逻辑）强化

- 保留 `* -> Cancel()`，并确保 `Cancel()` 执行后：
  - `PressNum=0`
  - `InputData[]` 清零
  - `ReInputEn/ReInputReady/ReInputCont` 清零
  - OLED 回到 `Input Password`

#### D) 断电中途输入

- 当前已满足：`DataInit()` 在启动流程中执行，`PressNum/InputData` 不持久化。
- 建议上电提示一行：`LAST INPUT CLEARED`（可选，便于测试确认）。

## 4）修改说明（给开发/测试）

1. 本次改动不改变密码规则（仍 6 位）。
2. 仅优化输入链路“连续性与优先级”，降低 ESP 干扰。
3. 压测必须覆盖“报警 + 联网 + 输入”复合场景，单场景通过不足以说明稳定。

---

## 5）当前不足与后续建议

- 仍存在部分阻塞式 `delay_ms` / AT 等待，建议后续改成非阻塞状态机。
- `main.c` 仍偏大，建议拆分：`input_fsm.c / ui_render.c / net_sched.c / security_logic.c`。
- 建议补充自动化回归：串口脚本注入按键与网络指令，持续跑 2~4 小时稳定性。

---

## 6）一句话结论

该方案可在不重构整体架构的前提下，快速提升“矩阵键盘连续输入稳定性 + 联网场景交互流畅度”，并给出可执行压测标准，便于实机验收与论文答辩展示。
